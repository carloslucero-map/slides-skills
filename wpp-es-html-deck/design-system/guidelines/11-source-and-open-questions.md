# Source and open questions

## Where this system comes from

The system was built on 2026-09-21 from [`carloslucero-map/slides-skills`](https://github.com/carloslucero-map/slides-skills) at `main@8fea060`, package `wpp-es-html-deck`. Every value was lifted from the code that shipped decks (the stylesheet generated by `scripts/build_shell.py` and the master design guideline it enforced), not from a screenshot or a reading of the brand book. `components/bundle.css` was lifted from a real generated deck rather than hand-copied.

Since then it has been adapted for Claude Design: text styles wired to four single-weight faces, a Slides recipe on each Elements card, five added elements (ColumnLabel, Takeaway, CardLink, LogoRow, ScreenshotFrame) and four fixed slides (cover, agenda, divider, thank-you), the layouts regrouped by argument family and marked as showcase pages, a layout catalogue in the README, and card guidelines rewritten for Claude Design.

## Where it is edited

Here, in Claude Design. The system is the source and the repository follows it: `authoring/refresh_design_system.py` copies it one way into the `wpp-es-html-deck` skill, recording this system's version and a hash for every file and layout it copies; the skill builds its decks from that copy, and the deck verifier fails a deck when the copy has been edited by hand. Nothing in the repository writes back. Never re-sync this system from the repository: it would overwrite the edits made here.

On 2026-09-25 four gaps against the generator were closed here: the content edge is settled at 40px, the agenda
rows sit where the generator places them, the dark outro and the dots and playbook covers were added, and the two
logos were re-uploaded with their fill on each shape (the first uploads had lost it with their `<style>` block and
rendered black). Later that day the Headline card gained the Slides highlight's word-space gap and length limits and the two-line eyebrow rule, and the traced layouts' Origin lines were pointed at the repository's current paths.

## Open questions

- **The default headline size.** `headline` at 54px survives from a retired ×1.5 point conversion; the bank's own decks measure 64px (`headline-lg`), which the traced layouts use. The default has not been re-decided.

## Known gaps

- **Per-deck role variables are not tokens.** `--dv-*` (divider colourway) and `--ty-*` (outro) are resolved per deck from the spec's `dividerColourway` and `outro` keys across six colourways and two outros. They are build outputs, not stable values, so the Colour guideline documents them instead.
- **The indigo-violet ramp** (`#0A1E78 · #323CAA · #6464D2 · #AA96FF · #D2BEFF`) is reference only in the source: it belongs to the wider WPP pillar system, not the ES ramp. Only its head is tokenised, as `tert-indigo`.
- **Motion is not tokenised.** The system has a runtime choreography layer with three levels (`full`, `subtle`, `off`), auto-disabled for reduced motion, print and headless capture. The token format has no motion family, so it is documented in the Motion guideline only.
- **No component bundle.** The elements and layouts are documented HTML, not a JavaScript library, so there is nothing for a Design canvas to mount. A bundle of the elements is worth building only if the team makes WPP visuals (posters, one-pagers) on a Design canvas; decks gain nothing from it.
- **Media wells render empty.** Layouts that host illustrations, photos or screenshots show the composition and its type; the media areas are blank.
- **Licensing.** The repository's `NOTICE.md` marks the fonts, logos and illustrations as proprietary to WPP and not for redistribution, and records that the 13 photographs have **no verified licence**. The caveat is repeated on each asset group.
